## Goal

Share AGENTS.md, agents, skills, and plugin config across all 6 Wywy repositories on one server. Everything lives within Wywy repos — no global `~/.config/opencode/` modification.

## Architecture

```
/etc/Wywy-Website-Control/          ← canonical source of truth
  .opencode/                         ← agents, skills, package.json
  AGENTS.md                          ← all conventions + control-specific
  AGENTS.shared.md                   ← generic conventions only (API naming, languages, exceptions)
  opencode.json                      ← default_agent, permission, instructions: ["AGENTS.md"]
  share-config.sh                    ← wires other repos into shared config

/usr/local/Wywy-Website/<each-repo>/
  .opencode/ → /etc/Wywy-Website-Control/.opencode   ← symlink
  opencode.json                                       ← committed: default_agent, permission,
                                                         instructions: ["AGENTS.md", "{file:...AGENTS.shared.md}"]
  AGENTS.md                                           ← committed: repo-specific content
```

## How it works

- **`.opencode` symlink** — each repo symlinks `.opencode/` → control repo's `.opencode/`. All repos share the same agents (`build`, `plan`), skills (`grill-me`, `grill-with-docs`, `test`), and npm plugin package.
- **`AGENTS.shared.md`** — generic Wywy conventions (naming, languages, exception rules). Referenced via `{file:}` in each repo's `opencode.json`.
- **Per-repo `AGENTS.md`** — repo-specific instructions committed by each repo owner.
- **Config merging** — OpenCode merges the `instructions` arrays from all instructions sources. De-duplication prevents the control repo from double-loading if its own AGENTS.md overlaps with AGENTS.shared.md (control repo doesn't reference AGENTS.shared.md).
- **`opencode.json`** — each repo has `default_agent: "build"`, workspace permissions, and both instruction files. Control repo uses only `["AGENTS.md"]` (its AGENTS.md already covers everything).

## AGENTS.md (control repo)

Keeps all current content (control commands + generic conventions). Convention file references use absolute paths into `/etc/Wywy-Website-Control/internal/conventions/`.

## AGENTS.shared.md (control repo)

Generic Wywy conventions stripped from the control repo's AGENTS.md content:
- API naming conventions
- Language-specific conventions
- Convention exceptions rule

All paths are absolute into the control repo.

## Per-repo committed files

- `opencode.json`: full config (`default_agent`, `permission`, `instructions: ["AGENTS.md", "{file:/etc/Wywy-Website-Control/AGENTS.shared.md}"]`)
- `AGENTS.md`: empty skeleton or `# <repo-name>` header — filled in by repo owner

## share-config.sh

- Creates/verifies `.opencode` symlink to control repo
- Writes `opencode.json` with correct `instructions` array
- Creates `AGENTS.md` skeleton if missing (never overwrites existing)
- Called from each service install script in `scripts/install/` after repo clone + permissions

## Migration steps (completed)

1. Created `AGENTS.shared.md` in control repo with generic conventions
2. Updated control repo `AGENTS.md` convention paths to absolute, dropped git workflow section
3. Updated control repo `opencode.json` with `default_agent` and `permission`
4. Created `share-config.sh`
5. Wired `share-config.sh` into all 4 service install scripts (`backup.sh`, `cache.sh`, `master-database.sh`, `website.sh`)
6. Ran `share-config.sh` against all existing repos under `/usr/local/Wywy-Website/`
