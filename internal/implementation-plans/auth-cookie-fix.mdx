## Problem

In-app page navigation within the Capacitor app causes one of the two auth cookies (master-database `session` or cache `sessionid`) to be dropped by WKWebView. Which cookie survives is non-deterministic.

### Root cause

The Capacitor WebView loads from an origin (`localhost`) distinct from both backend origins (`db.ericzhu.me`, `cache.ericzhu.me`). Every `fetch()` request is cross-site. Three conditions combine to cause the drop:

1. **iOS Intelligent Tracking Prevention (ITP)**: As of iOS 14, WKWebView applies ITP. Without `WKAppBoundDomains`, persistent cookies for third-party domains are blocked or evicted after arbitrary heuristics.

2. **`SameSite` default mismatch**: If a server's `Set-Cookie` response omits `SameSite`, WKWebView defaults to `SameSite=Lax`. A `Lax` cookie is NOT sent on cross-site `fetch()` POST requests — only on top-level GET navigations. The `whoami()` call uses POST, so the cookie appears "forgotten."

3. **`Secure` flag rejection**: The Capacitor app used `iosScheme: 'http'`, loading from `http://localhost`. WKWebView rejects `Secure`-flagged cookies set from a non-HTTPS context (RFC 6265bis). This prevented the CSRF `csrftoken` cookie from being stored natively.

## Changes Made (Capacitor App)

See the website repo for the implemented fixes:

| File                                                            | Change                                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `apps/capacitor-app/ios/App/App/Info.plist`                     | Added `WKAppBoundDomains`: `ericzhu.me`, `db.ericzhu.me`, `cache.ericzhu.me`          |
| `apps/capacitor-app/capacitor.config.ts`                        | `iosScheme: 'http'` → `'https'`                                                       |
| `apps/capacitor-app/ios/App/App/WywyBridgeViewController.swift` | Native cookie bridge now sets `.sameSitePolicy`                                       |
| `apps/http/src/http.ts`                                         | Skip `document.cookie` in Capacitor context; pass `sameSite: "none"` to native bridge |

## Server-Side Changes Needed

### Master-Database (`sql-receptionist`)

**Repo**: Wywy-Website-Master-Database  
**File**: auth cookie-setting code in `apps/sql-receptionist/src/`

1. Add `SameSite=None; Secure` to the session cookie `Set-Cookie` header:

   ```
   Set-Cookie: session=<token>; HttpOnly; Path=/; Secure; SameSite=None
   ```

   - `Secure` is required because `SameSite=None` demands it per the spec
   - `HttpOnly` prevents XSS access to the session token
   - Do NOT set `Domain=.ericzhu.me` — keep it host-scoped to `db.ericzhu.me`

2. Verify the cookie name `session` does not collide with the cache's cookie name. If the cache also uses `session` (instead of Django's default `sessionid`), rename one. Two cookies with the same name on sibling subdomains can overwrite each other if either sets a parent-scoped `Domain`.

3. Ensure CORS OPTIONS preflight handler returns:
   ```
   Access-Control-Allow-Origin: https://ericzhu.me
   Access-Control-Allow-Credentials: true
   ```
   The origin must be explicit (not `*`) when `credentials: "include"` is used.

### Cache (Django)

**Repo**: Wywy-Website-Cache  
**File**: `apps/sync/sync/settings.py`

```python
SESSION_COOKIE_SAMESITE = 'None'
SESSION_COOKIE_SECURE = True
SESSION_COOKIE_HTTPONLY = True  # already Django default

CSRF_COOKIE_SAMESITE = 'None'
CSRF_COOKIE_SECURE = True
```

Do NOT set `SESSION_COOKIE_DOMAIN` or `CSRF_COOKIE_DOMAIN` — leave them `None` so cookies are host-scoped to `cache.ericzhu.me`.

After applying server-side changes:
